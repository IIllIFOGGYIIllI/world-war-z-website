Why v2:
The first false-error patch fixed the runtime behaviour but changed two literal
authentication-restore guard strings that scripts/validate_site.py intentionally
checks. This version preserves those existing terminal-authentication guards and
separates navigation/UI restore failures into their own non-auth failure path.

Runtime behaviour:
- Genuine configureDiscordAuth/bootstrap failure:
  keeps the existing unavailable=true terminal authentication guard.
- Later showView/navigation restore failure:
  uses a normal login state and DOES NOT claim Discord verification is unavailable.

Validator compatibility:
- const failDashboardBootstrap = (error) =>
- window.WWZServerContext?.showLogin({ unavailable: true });
- No protected action was sent
