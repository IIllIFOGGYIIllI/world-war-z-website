WHAT M10 MEANS
Milestone 10 is the Admin-facing operational intelligence pass. It builds on the
existing protected Command Centre and existing Railway aggregate endpoint instead
of introducing another polling worker or another database.

THIS TEST ADDS
- Overall operational-health score (0-100) with Healthy / Watch / Degraded / Critical states.
- Health deductions use existing real Command Centre data only:
  DayZ/Nitrado state, Discord readiness, restart sync, delivery failures,
  moderation deadlines, notification failures, configuration failures and the
  existing operational failure queue.
- Automation Watch for:
  * restart scheduler
  * Discord gateway
  * Nitrado link
  * automatic deliveries
  * notification routing
  * moderation deadlines
  * configuration checks
  * failure/retry queue
- Central "Needs Attention" list is upgraded:
  backend-provided attention signals are kept, and important existing aggregate
  conditions are added only when not already present.
- Signals are severity sorted and jump directly to the relevant specialist page.
- 30-second refresh remains bounded to the active Command Centre view.
- Stale-data detection after 75 seconds.
- If a refresh fails after a successful load, the last known snapshot stays on
  screen and is clearly marked stale instead of blanking the Admin overview.
- Manual refresh shows Refreshing… feedback.
- PWA revision bump included.

NO BOT / DB / DAYZ CHANGE
This phase uses the already-deployed /api/admin/command-centre aggregate. There is
no new Nitrado loop, no database migration and no DayZ mission change.
