WWZ false Discord error + PWA update push hotfix

UPDATED FILES ONLY
- assets/js/dashboard/bootstrap.js
- sw.js

Root cause fixed:
The Discord auth config succeeds first, which enables the sign-in button. Immediately
afterward the signed-out reset calls resetAppealPanels(), but appeals.js is intentionally
lazy-loaded and is not present on the initial gateway. That ReferenceError propagated
back into bootstrap and was incorrectly rendered as:
"Discord verification is temporarily unavailable."

bootstrap.js now supplies a temporary safe reset fallback until appeals.js is loaded.
The existing real authentication-failure guard remains intact for genuine outages.

PWA behaviour:
sw.js now contains WWZ_PWA_UPDATE_REVISION. Bump this token for every deployed website
update so installed PWAs/TWAs detect a new service worker and surface the existing
"Update Now" flow. This hotfix also invalidates the cached bootstrap.js specifically,
without clearing users' bounded map/tile caches.

Suggested commit:
Fix Discord gateway false error

Testing:

4. On the signed-out gateway, the Discord button should remain enabled and the notice
   should read the normal secure-verification message, not the red unavailable error.
5. Complete a Discord sign-in to confirm normal auth still works.
